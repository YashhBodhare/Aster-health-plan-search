# Contributing to the documentation

This is a business-analysis portfolio repository. Contributions should keep the requirements and downstream artifacts aligned.

- Mark each statement as a source requirement, proposed solution, assumption, or approved decision where its status matters.
- Preserve requirement, gap, solution-map, story, and test traceability IDs. Reconcile the current ID differences before baselining.
- Record decisions with approver, date, rationale/evidence, and impacted artifacts in `docs/OPEN-DECISIONS.md`.
- Keep the survey dataset explicitly simulated; do not present it as actual research.
- Use synthetic examples only. Do not commit personal health information, member records, credentials, production endpoints, or private stakeholder contact details.
- Use relative links and update `docs/DELIVERABLES.md` when adding or renaming artifacts.
- Use a pull request to review scope, terminology, traceability, and any change to expected behavior.
- Do not add a license until publication rights for included assets are confirmed.
